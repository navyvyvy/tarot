## Findings considered and rejected

- Virtualizing the 78-card dictionary: 78 local images and cards are a fixed,
  bounded set; the extra machinery is not justified until profiling shows a
  real interaction problem.
- Splitting `app.js` again: its major domains are already separated into
  `summary.js`, `detail.js`, `dictionary.js`, and `core.js`; another extraction
  would create churn without fixing a current defect.
- Adding analytics: no provider, consent policy, or product question has been
  chosen. Add it only when a concrete metric will drive a decision.
- Dynamic per-reading Open Graph images: static GitHub Pages cannot generate
  per-URL metadata. Revisit only if a server or edge function is authorized.
- Reading history/journal and notifications: these add persistence and privacy
  decisions, and saved readings were explicitly deferred.
- Native app wrappers: the PWA should first prove repeat use. Android TWA or an
  iOS wrapper becomes worthwhile after retention data or native-only value
  exists.
- Store-grade PNG/maskable icons, screenshots, and a privacy page: important
  before an app-store submission, but they do not block the current web/PWA
  experience. Treat them as a release checklist, not an immediate refactor.
- A broad CSP rewrite: the app is static, same-origin, and does not render URL or
  form input through `innerHTML`. Revisit if third-party scripts or a backend are
  introduced.
